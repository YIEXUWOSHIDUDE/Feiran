# Feiran 项目计划书与功能使用指南

更新日期：2026 年 10 月 23 日。

Feiran（斐然）是一个面向个人求职材料准备的网页工作台。用户导入个人简历和岗位描述后，可以筛选岗位、查看岗位要求与匹配提示、让 AI 生成岗位简历，再局部修改、整理为一页并下载 PDF。

当前已具备完整的材料准备流程。四轮架构改进和一页整理功能均已合并、部署；英文线上流程已验证到实际 PDF 下载。当前实现仍要求批准后才能生成最终 PDF，与最新“人工审核可选”的产品目标存在差距，列入后续计划。

本计划书以发布提交 `4c595a7afef0d3fac3f559654177d2a0af508c36` 为状态基线。部分旧文档仍保留“尚未部署”等历史表述，当前状态以本计划书和开发记录顶部的最新验收为准。

## 一 项目目标与范围

### 产品目标

让用户把重复的岗位阅读和简历整理工作集中到一个地方，得到可继续修改、可保存、可下载的岗位简历。

- **岗位理解**：保存岗位原文、来源和获取时间，提取要求，展示相关技能及 Sponsor 信息。
- **材料生成**：结合个人资料和岗位要求，由 AI 直接改写并生成完整内容。
- **局部调整**：采用建议、编辑单条内容、撤销或重做，不因局部操作重新生成整份简历。
- **材料输出**：保留版本和改动记录，按需要做一页内容取舍，导出 PDF。

AI 可以扩写和补充候选人内容，不要求用户逐条确认事实后才能生成。采用建议表示选择文案，不表示系统核实了现实经历。雇主的岗位信息、招聘状态和 Sponsor 声明仍以来源原文为依据。

### 当前范围

当前重点是已有账号的云端使用和个人材料准备，不开放自助注册。代码已有 V2 账号隔离与任务管理能力，但这不等于已开放多人服务，也不等于完成了面向 100 人的线上容量验收。

自动投递、申请表填写、邮件发送、投递进度跟踪、付费订阅、团队协作、扫描件 OCR、全网岗位采集和移动应用不属于当前已交付功能。

| --- | --- | --- | --- |
| 登录与个人工作区 | Cognito 登录、退出、服务端会话和按用户隔离的数据访问 | 通过云端地址登录，读取自己的资料、岗位和材料 | 当前不开放自助注册 |
| 个人简历导入 | 上传带文本的 PDF，解析经历与栏目，保存个人资料 | 上传时选中文或英文，查看解析结果后保存 | 暂不识别扫描件；上传限制以页面提示为准 |

| 岗位筛选与排序 | 关键词、地点、地区、资深及管理岗位过滤、Sponsor 筛选；按资料技能词排序 | 在岗位列表设置筛选，打开具体岗位 | 技能重合不是录取概率或完整资格判断 |
| Sponsor 提示 | 支持、不支持、有条件、未知、信息矛盾等状态及原文依据 | 列表和详情查看；必要时点击“检查担保表述” | 依据当前保存的正文和规则，不推断个人签证资格 |
| 岗位要求管理 | 提取要求、查看原文、手动补充和调整要求 | 准备岗位后查看要求列表 | AI 可能漏提取或误解；手动调整会影响后续检查有效性 |
| 岗位简历生成 | 按岗位改写、调整内容布局，保留阶段结果 | 点击“准备简历”，等待任务完成后查看预览 | AI 调用可能失败；阶段失败与成功分别显示 |
| 要求对照检查 | 对照当前语言简历与岗位要求，保存检查结果 | 点击“立即检查”或“重新检查” | 打开、切换或刷新岗位不自动重复付费检查；过期结果会标记 |
| 完整 AI 建议 | 针对要求生成完整句子或技能项，保存后可复用 | 在对应要求下点击“AI 建议填写” | 建议可以扩写个人资料；不会把它标成已核实经历 |
| 局部采用与填写 | 逐字采用所选内容，或自行填写并选择位置 | 对建议点击采用，或填写自己的文字 | 只改当前岗位简历，不自动写回个人资料 |
| 局部编辑与撤销 | 修改单条内容，撤销、重做，并显式保存到个人资料 | “编辑这份简历”；需复用时点“保存到个人资料” | 保存到个人资料与保存当前岗位修改是两个动作 |
| 一页整理 | 依据岗位相关度省略部分内容，用真实打印页数确认结果 | 点击“压缩为一页”，查看省略记录，可撤销或重做 | 不缩小字号，不自动压缩每句话，也不保证所有简历都能变一页 |
| 预览与 PDF | 预览、批准具体版本、生成并下载最终 PDF | “批准这份简历 → 生成最终 PDF → 下载最终 PDF” | 这是当前操作方式；取消强制批准仍待实现 |
| 任务与用量 | 后台任务状态、取消、重复请求处理、额度预留与模型用量记录 | 页面显示处理进度、错误及账号额度 | 用量记录不等于实际美元账单；取消不保证已发出的模型请求不计费 |
| 编辑状态保护 | 轮询和标签页内导航保留草稿；拒绝旧页面覆盖新版本 | 保存冲突时保留输入，可复制或放弃草稿读取新内容 | 未保存草稿只在标签页内存中，整页刷新或关闭会丢失 |
| 云端运行与运维 | HTTPS、容器发布、持久化数据、备份恢复及健康检查工具 | 云端直接使用；运维操作由部署脚本和管理命令完成 | 备份与跨环境恢复的完整线上演练另有验收范围 |

## 三 从导入到下载的使用流程

### 1 登录工作台

打开 [Feiran 云端工作台](https://d1a15e5eqq0d7e.cloudfront.net)，使用已配置的账号登录。云端使用不需要在自己电脑安装 Python 或配置模型密钥。

右上方的简体中文或 English 切换只影响界面文字。要生成另一种语言的简历，需要先保存对应语言的个人资料。

### 2 上传并保存个人资料

进入个人资料页面，选择中文或英文，上传可选中文字的 PDF。查看提取出的栏目和经历，修正明显的解析错误后保存。

保存后的资料即可参与岗位排序、匹配和简历生成，无需逐条做真实性确认。重新上传只更新所选语言，旧版本保留在历史中。

### 3 选择或导入岗位

可以从以下三个入口开始：

1. **已有岗位链接**：进入“我的岗位 → 新增岗位”，输入公开岗位 URL。
2. **已有岗位正文**：粘贴完整 JD，并尽量填写标题、公司和来源 URL。
3. **浏览关注公司**：进入“发现岗位”，添加支持的招聘来源并刷新，再按关键词、地区和其他条件筛选。

云端 V2 先保存并展示岗位，让你查看原文、Sponsor 和技能提示；选择“准备简历”后才进入要求提取及简历生成。重复输入已保存的链接会打开已有岗位。

网页读取失败时，可以手动粘贴正文继续。保存的 JD 是获取当时的快照，准备申请时仍应打开官网核对是否在招。

### 4 生成岗位简历

打开岗位，选择已经上传的简历语言，点击“准备简历”。页面会显示任务进度，完成后可以查看岗位要求、生成的简历及内容调整。

这里有两个不同对象：**个人资料**是跨岗位复用的素材；**岗位简历**是为这一岗位生成和编辑的材料。对岗位简历做局部修改，不会自动改变其他岗位的素材。

### 5 按需要检查和补充内容

点击“立即检查”或“重新检查”，查看当前简历如何体现岗位要求。对需要补充的要求，可以点击“AI 建议填写”，采用生成的完整内容，也可以自行填写。

采用后内容直接进入当前岗位简历，不会触发整份重写。需要调整措辞时，在“编辑这份简历”中修改对应条目并保存。需要让这条内容用于其他岗位，再单独点“保存到个人资料”。

例如，针对一个 Python 后端岗位采用一条 API 项目描述，它只进入这份岗位简历；保存到个人资料后，未来准备其他岗位时才可复用这条素材。

### 6 两页时整理为一页

如果内容过长，点击“压缩为一页”。系统按照岗位相关度选择可省略内容，并通过实际 PDF 打印检查是否达到一页。

该步骤保留已采用或局部编辑的内容、用户恢复的内容、必要教育信息，以及经历和技能的最低保留内容；原始个人资料不被删除。省略记录会展示在改动列表中，可以撤销或重做。部分整栏省略会作为一个改动项恢复。

若保护内容太多或仍无法装入一页，系统会说明原因并保留原稿。此时可自行精简长句，或接受两页。撤销省略、继续编辑或重新准备后，页数可能变化，需要再次整理或导出确认。

此步骤本身不调用 DeepSeek，不增加模型 token 用量。

### 7 下载最终 PDF

当前版本需要先点击“批准这份简历”，再点击“生成最终 PDF”，待完成后点击“下载最终 PDF”。批准后若再次编辑、采用或压缩，需重新批准最新版本。

下载后检查页数、文字是否完整、联系方式和链接是否正确。一页整理的英文线上样例已验证为两页变一页，字号不变，无截断或重叠。

产品目标是将人工审核改成可选，这一节描述的是当前真实操作，不代表最终设计。

## 四 常见情况与处理方式

| 页面情况 | 含义 | 操作 |
| --- | --- | --- |
| Sponsor 显示未知 | 当前正文没有被规则识别到明确结论 | 展开原文查看，不把未知当作拒绝 |
| 检查显示待复查或上次核验 | 简历或相关输入已改变，旧结论可能不再适用 | 需要新结论时主动重新检查 |
| 其他标签页已经修改内容 | 保存请求基于旧版本，系统拒绝覆盖新内容 | 先复制未保存文字，或放弃草稿读取最新版本后重写 |
| 任务失败或被取消 | 这次操作没有完成，已有可用部分仍可保留 | 阅读具体错误；有重试入口时按需重试，不把失败当作生成成功 |
| 一页整理失败 | 当前可省略内容不足以把实际 PDF 降到一页 | 手动缩短文字、调整内容，或保留两页 |
| 刷新后未保存文字消失 | 草稿只保存在当前标签页内存 | 修改后及时保存；刷新前复制需要保留的文字 |
| 导出要求重新批准 | 当前内容已不同于上次批准版本 | 目前需批准最新版本再导出 |
| 额度不足或暂不接收任务 | 账号或站点的任务限制生效 | 按页面提示等待或由管理员调整；刷新不能绕过限制 |

## 五 技术实现与运行方式

### 当前实现

| 层次 | 当前技术与职责 |
| --- | --- |
| 页面 | 原生 HTML、CSS、JavaScript，提供中文和英文界面 |
| Web 服务 | Python、FastAPI、Uvicorn；本地 V1 与云端 V2 保留不同的存储和身份适配 |
| 文本生成 | DeepSeek 承担解析、要求提取、改写、布局建议和对照建议等模型任务 |
| 业务状态 | V2 使用 SQLite 和私有文件；资料、岗位、材料、任务与用户归属关联 |
| 准备流程 | `cv_preparation.py` 共享改写、布局和局部内容恢复流程；当前未采用 LangGraph 编排 |
| 编辑与一页整理 | `cv_edit.py` 处理局部操作；`cv_fit.py` 用确定规则选取省略内容，再调用打印检查 |
| PDF | 使用 Chrome 或 Chromium 将受控 HTML 模板打印为 PDF；上传解析使用 pypdf |
| 云端 | AWS CloudFront 提供 HTTPS 入口，Cognito 处理登录；应用容器运行在 EC2，使用 EBS 数据卷和 S3 备份 |
| 发布 | GitHub Actions 执行测试和构建，再通过既有发布流程安装到目标环境 |

任务状态保存在数据库，执行器在一个应用进程内限制并发；当前没有新增 Redis、Celery 或微服务。Jev 是可选实验，不是默认生成流程的必要组成部分。

### 本地运行

云端用户可以跳过此节。本地 V1 与云端 V2 的账号、任务及数据行为不完全相同，数据也不会自动同步。

在独立目录获取仓库，安装 Python 3.14 及 Chrome 或 Chromium 后，运行：

```sh
git clone https://github.com/YIEXUWOSHIDUDE/Feiran.git
cd Feiran
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
mkdir -p .local
```

将自己的 DeepSeek key 用编辑器保存到被 Git 忽略的 `.local/deepseek_api_key` 后，在同一终端运行：

```sh
chmod 600 .local/deepseek_api_key
export DEEPSEEK_API_KEY_FILE="$PWD/.local/deepseek_api_key"
.venv/bin/python web.py
```

打开 `http://127.0.0.1:8765/`。若浏览器无法自动找到，可设置 `CHROME_PATH` 为实际可执行文件路径。中文 PDF 需要支持中文的字体。Windows 命令见仓库 README，其本地端到端运行仍未完成验证。

AI 功能会把相关资料和岗位文字发送到 DeepSeek。应用有已知身份信息过滤，但经历本身仍可能识别个人，不能当作完全匿名。云端资料保存在云端私有数据目录，本地资料保存在本机数据目录。
